20.1 API Naming Convention
Naming api is important in web developing, till now before drf we have wrote the urls as we wish but now we need to maintain some rules while naming, so for this if an app have multiple urls, for example our product app has product and category models, so for this whole app we might register this as products in root urls.py but when we will try to view categories it will look like products/categories which is not a great naming convention, to overcome this, we have registered our api urls in root urls.py and both pproduct and category related in api apps urls, so in root urls.py:

from django.contrib import admin
from django.urls import path,include
from debug_toolbar.toolbar import debug_toolbar_urls

urlpatterns = [
    path("admin/", admin.site.urls),
    path('api-auth/', include('rest_framework.urls')),
    path('api/v1/', include('api.urls'))
]+ debug_toolbar_urls()

then api apps urls.py:
from django.urls import path,include

urlpatterns = [
    path('products/', include("product.product_urls")),
    path('categories/', include("product.category_urls"))
]

andin product app we would create 2 urls, one for product another for category:
category_urls.py:

product_urls.py:

20.2 Introduction to get_object_or_404get
Now if an object is not available and we don't handle it well it will shown an objectdoesnotexist error,but inapi building this does not look great for code readability so might write something like this :
from rest_framework.response import Response
from rest_framework import status

def view_specific_product(request, id):
    try:
        product = Product.objects.get(pk=id)
        product_dict = {
            'id': product.id,
            'name': product.name,
            'price': product.price
        }
        return Response(product_dict)
    except Product.DoesNotExist:
        return Response(
            {'message': 'Product does not exists'},
            status=status.HTTP_404_NOT_FOUND
        )
so this way if a code is not found then it will show a 404 not found error on rest frame work view with status code, but this can easily be done by get_objeect_or_404 method, here how we could have done it :
@api_view()
def view_specific_products(request,id):
    product=get_object_or_404(Product, pk=id)
    product_dict={"id":product.id, "name":product.name, "price":product.price}
    return Response(product_dict)
so if an object is not found then it will automatically show a 404 error

20.3 Django Serializer
Serializers are a way to convert you model data type to json or xml, its functionalty are similar to Django forms. so in our view sending the data by naming id, name, price etc are not suggested, hence we will use serializers to show our product data, so we will create a file named serializers.py and then based on the data we want to show would write them with  their appropriate feld name matching in models:
from rest_framework import serializers
from product.models import Product,Category
from decimal import Decimal

class ProductSerializer(serializers.Serializer):
    id=serializers.IntegerField()
    name=serializers.CharField()
    unit_price=serializers.DecimalField(max_digits=10, decimal_places=2, source='price')
    
    price_with_tax=serializers.SerializerMethodField(method_name='calculate_tax')
    
    def calculate_tax(self,product):
        return round(product.price * Decimal(1.1),2)

okay now here id and name has followed the same models pattern but their is no field named unit_price exits so to make our custom fieldname we would simply put source attribute with real fieldname, then what if we could have known the price with tax, to do tthat we would do the calculation on a function and put that function SerializerMethodField as method_name attribute's value.
and then in views.py:
@api_view()
def view_specific_products(request,id):
    product=get_object_or_404(Product, pk=id)
    serializer=ProductSerializer(product)
    return Response(serializer.data)
now her we passing the data to serializer which will map the product to the serializer field we defined, .data is where we will actually get the field name with value as dictionary format
